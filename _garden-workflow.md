## Tooling

| Tool | Role |
|------|------|
| [Better BibTeX for Zotero](https://retorque.re/zotero-better-bibtex/) | Auto-exports `_bib/library.json` while Zotero is open — full metadata including citekeys, tags, and connexe (related) items |
| [Better Notes for Zotero](https://github.com/windingwind/zotero-better-notes) | Optional — write notes inside Zotero and export to markdown |

## Note conventions

### Writing notes

Minimal frontmatter. Cite sources with standard `@citekey` (pandoc citation syntax):

```yaml
---
type: writing
title: "Aid fragmentation after disasters"
date: 2026-05-02
tags: [aid, fragmentation]
---

Climate disasters reshuffle aid flows toward non-state channels [@becerra2014disasters].
See also [Frot & Santiso on fragmentation](../sources/frot2011fragmentation.qmd).
```

### Source notes

Auto-generated by `_pre-render.py` from `library.json`. Contain metadata + connexe links + back-references only — no abstract, no inline notes:

```yaml
---
type: source
title: "Disasters and bilateral aid responsiveness"
authors: Becerra et al.
year: 2014
zotero-key: becerra2014disasters
tags: [aid, disasters, bilateral]
---

## Related to

- [Frot & Santiso (2011)](frot2011fragmentation.qmd) — Aid fragmentation and donor behavior

## Cited in

- [Aid fragmentation after disasters](../notes/aid-fragmentation.qmd)
```

**What `_pre-render.py` manages automatically:**
- YAML header (regenerated on every render from `library.json`)
- `## Related to` — populated from Zotero connexe field (`dc:relation` in Better BibTeX JSON)
- `## Cited in` — updated whenever a writing note adds or removes a `@citekey` citation

**What you manage manually** (if needed):
- Additional prose or commentary below `## Cited in`

## Better BibTeX setup (one time)

*You already use Better BibTeX for `.bib` citation export — this adds a second export in parallel and does not affect the existing one.*

1. In Zotero: **File → Export Library** → format: **Better BibTeX JSON** → tick **Keep updated** → save to `_bib/library.json`
2. Your existing `.bib` export continues to power `@citekey` citation rendering in Quarto documents
3. `_bib/` is gitignored — Zotero manages the file locally

---

## Daily workflow

1. Add or annotate a paper in Zotero (tags and connexe items included)
2. Open `garden/notes/` → create a writing note → cite with `@citekey`
3. Run `quarto preview` or `/publish` — `_pre-render.py` runs automatically, creates or updates the source note
4. `## Related to` and `## Cited in` populate from Zotero data

**Staleness warning:** if `library.json` is older than 24 hours, the script prints a non-blocking warning. Open Zotero before the next render to refresh it.

## Graph (Phase 2)

Once notes accumulate:

1. Extend `_pre-render.py` to emit `garden/links.json` — nodes are notes, edges are `@citekey` citations and connexe relations
2. Add an Observable JS block to `garden.qmd` that reads `links.json` and renders a force-directed graph

Observable JS is built into Quarto — no additional dependencies needed.
