# Personal Academic Website — Claude Code Guide

## Project Overview

Paul Vernus's personal academic website, built with Quarto.
Hosted at https://pvernus.github.io, deployed automatically
via GitHub Actions on every push to `main`.

## Directories to Leave Alone

- `_site/` — generated output, never edit manually, not committed
- `.quarto/` — Quarto cache, not committed
- `.claude/` — Claude Code config; agents/rules are for research workflows
- `_bib/` — Better BibTeX JSON export from Zotero, local only (gitignored), managed by Zotero
- `garden/sources/` — auto-generated source notes, managed by `_pre-render.py`; edit cautiously

## Common Commands

```bash
quarto preview      # Live preview with hot reload
quarto render       # Full build to _site/
quarto check        # Validate Quarto install
```

**Publish shortcut:**
```
/publish                        # commits everything with "Update site"
/publish Add new book to list   # commits with custom message
```

Or from terminal (after `source ~/.bashrc`):
```bash
publish "Add new book to list"
```

## Conventions

### Content
- Page content lives in `.qmd` files at the repo root
- Front matter is minimal — only override what `_quarto.yml` already sets globally
- `toc: false` is set globally; override per-page if needed

### Styles
- `styles.css` contains: background/link colors, dark mode overrides, badge styles, navbar fixes
- Avoid inline styles in `.qmd` files
- Add new per-element CSS to `styles.css` with a comment

### Dark Mode
- Toggle: sun/moon icon in navbar (respects OS preference on first load)
- Only three things change between modes:
  1. **Profile image** — swapped by JS snippet at bottom of `index.qmd`
  2. **Deezer link** — hidden in light mode via `body.quarto-light .about-link[href*="deezer"]`
  3. **Help nav item** — hidden in light mode via `body.quarto-light .navbar-nav li:has(a[href*="blog"])`
- All other colors/fonts are forced identical in both modes via `body.quarto-dark` overrides

### Blog Posts
- 3 posts under `blog/posts/`: read, watch, listen
- **Read** (`_read.md`): Title | Author | Year | ISBN | Category — books and articles merged; for articles, embed the URL in the Title as a markdown link
- **Watch** (`_watch.md`): Title | Creator | Year | Category — movies, TV shows, and videos merged; add type tag (Movie / TV Show / Video) to Category; for videos, embed the URL in the Title
- **Listen** (`_listen.md`): Title | Artist | Date | Category — music and radio
- **To add a row:** edit `blog/posts/<post>/_<post>.md`, add new row at the **top**, then update `date-modified:` in that post's `index.qmd`
- Each table has a live filter input (type to filter any column)
- Category badges: use `<span class="tag">Label</span>` in the Category column

### Navigation
- Add new top-level pages: create `.qmd` + add to `website.navbar` in `_quarto.yml`
- `blog/` subdirectory is the blog; new posts go in `blog/posts/`

### Garden
- Writing notes go in `garden/notes/*.qmd` — authored manually, cite sources with `@citekey`
- Source notes in `garden/sources/` are auto-generated by `_pre-render.py` on every render
- `_bib/library.json` must exist (Better BibTeX JSON export from Zotero) for source notes to generate
- **Citations resolve via `garden/_cited.json`**, a pruned CSL JSON of only the works the
  garden cites, generated by `_pre-render.py` and **committed**. `_bib/library.json` is
  gitignored, so without this the published site renders every `@citekey` literally as
  `[@latour2017]`. `bibliography:` is set once in `_quarto.yml` — never per note, since a
  per-note field overrides it with a path CI does not have
- **Tags are inherited, not hand-written.** `_pre-render.py` reads Zotero tags from
  `~/Zotero/zotero.sqlite` (override with `ZOTERO_DATA_DIR`) and merges the tags of a
  note's cited references into its `tags:` field. A tag must be shared by ≥2 cited
  references to carry over. Tags are lowercased and kebab-cased; workflow tags, JEL
  codes, and plugin error tags are dropped. Add tags by hand only for things Zotero
  doesn't know (`FR`, `utopia`). Inheritance only adds — it never removes.
- Tag data comes from the Zotero database, **not** `library.json` — Zotero's CSL JSON
  export drops tags entirely, so every entry lacks the `keyword` field
- **Voice learns from Zotero highlights, not from source prose.** `/voice study` mines
  highlights on cited works into `garden/.voice/candidates.md`, which `/voice mentor`
  turns into forced-choice questions. Citation is not admiration — most cited works are
  journal prose the profile bans, so only the *selection* within a source counts
- **Highlights live in three stores, and all three must be read.** (1) attachment
  annotations on PDFs and EPUBs, via `zotero_get_annotations`; (2) `background-color`
  spans inside a Zotero note, where print-read books and FR sources land; (3) e-reader
  exports pasted into a note under the sentinel first line `Highlights export`, plain
  text with no colour. Reading only store 1 silently discards the FR and book half of
  the library — that was the Run 1 bug
- **Highlight colour taxonomy (user-confirmed):** yellow `#ffd400` = full-sentence claim,
  purple `#a28ae5` = thesis, blue `#2ea8e5` = number / empirical fact, orange `#f19837` =
  concept, green `#5fb236` = citation to chase. Yellow, purple and blue pool for style
  metrics; blue density is the anchoring measure, so it is computed over the coloured
  stores only
- See `_garden-workflow.md` for full setup instructions and note conventions

### Images
- Place images at the repo root; reference with relative paths: `image: profile.jpg`
- Images referenced only in JS must be listed under `project.resources` in `_quarto.yml`

### Git
- Commit source files only — `_site/` is gitignored
- Commit message format: imperative mood, e.g. `Add book to list`

## Deployment

Push to `main` → GitHub Actions renders with Quarto → deploys via GitHub native Pages API.
Site is live at https://pvernus.github.io within ~2 minutes.

Source: `.github/workflows/publish.yml` (two jobs: `build` → `deploy`)
